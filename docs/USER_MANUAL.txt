3.1 UNDERSTANDING DRIVE MAPPING
─────────────────────────────────────────────────────────────────────────

WHAT IS DRIVE MAPPING?
Drive mapping assigns a drive letter (like Z:) to a network location,
making it appear as a local drive in Windows Explorer.

BENEFITS:
• Easy access through File Explorer
• Works with all Windows applications
• Persistent across reboots (if configured)
• No need to remember network paths

DRIVE TYPES IN DRIVEMAPPER PRO:
1. Network Drives (SMB/CIFS) - Traditional Windows shares
2. Mounted Cloud Storage - Cloud providers as local drives
3. SFTP Mounts - Remote Linux/Unix servers
4. WebDAV Mounts - Web-based storage
5. NFS Mounts - Unix/Linux file sharing


3.2 SUPPORTED PROTOCOLS
─────────────────────────────────────────────────────────────────────────

SMB/CIFS (Server Message Block):
• Windows file sharing protocol
• Format: \\server\share or \\192.168.1.50\folder
• Supports authentication
• Native Windows support
• Best for: Windows servers, NAS devices, Samba shares

CLOUD (Rclone):
• Supports 40+ cloud providers
• Format: remotename:path
• Requires rclone configuration
• Best for: Google Drive, OneDrive, Dropbox, S3, etc.

SFTP (SSH File Transfer Protocol):
• Secure file transfer over SSH
• Format: hostname or IP address
• Requires SSH credentials
• Best for: Linux servers, web hosts

WebDAV (Web Distributed Authoring and Versioning):
• HTTP-based file access
• Format: hostname or URL
• Supports HTTPS
• Best for: Nextcloud, ownCloud, SharePoint

NFS (Network File System):
• Unix/Linux file sharing
• Format: server:/export/path
• Requires NFS client
• Best for: Linux/Unix servers


3.3 ADDING YOUR FIRST DRIVE
─────────────────────────────────────────────────────────────────────────

STEP-BY-STEP WALKTHROUGH:

1. SELECT PROTOCOL
   - Open the "Drive Mapper" tab
   - Click the protocol dropdown (default: SMB)
   - Choose your protocol type
   - The path placeholder will update to show the correct format

2. CHOOSE DRIVE LETTER
   - DriveMapper Pro suggests an available letter
   - You can change it if needed
   - Letters A: and B: are reserved for floppy drives
   - C: is your system drive
   - Common practice: Use Z:, Y:, X:, etc. working backwards

3. ENTER NETWORK PATH
   For SMB: \\server\share
   For Cloud: remotename:path
   For SFTP: hostname.com
   For WebDAV: webdav.hostname.com
   For NFS: 192.168.1.60:/export/share

4. AUTHENTICATION (If Required)
   - Enter username
   - Enter password
   - Leave blank if no authentication needed

5. OPTIONAL SETTINGS
   - Display Name: Friendly name for this drive
   - MAC Address: For Wake-on-LAN feature

6. VALIDATE & ADD
   - Click "✅ Validate & Add"
   - DriveMapper Pro will test the connection
   - If successful, drive is saved to your profile
   - If failed, check logs for error details

7. MAP THE DRIVE
   - Find your drive in the "Saved Drive Profiles" section
   - Click "▶ Map" button
   - Drive should appear in File Explorer
   - Status panel will update to show the mapped drive

EXAMPLE: Adding a Windows Share
Protocol: SMB
Drive Letter: Z
Path: \\192.168.1.50\Media
Username: admin
Password: mypassword
Label: Media Server

After clicking "Validate & Add" and then "Map", you'll have Z: drive
pointing to your media server.


3.4 MAPPING VS MOUNTING
─────────────────────────────────────────────────────────────────────────

TERMINOLOGY:
• Mapping: Used for SMB/CIFS network shares
• Mounting: Used for cloud storage, SFTP, WebDAV, NFS

TECHNICAL DIFFERENCE:
Mapping uses Windows native networking (WNetAddConnection2 API)
Mounting uses rclone to create a virtual filesystem

FROM USER PERSPECTIVE:
Both appear as drive letters in File Explorer and work the same way.

PERFORMANCE CONSIDERATIONS:
• SMB Mapping: Direct network access, very fast
• Rclone Mounting: Goes through rclone layer, slight overhead
• Cloud Mounting: Depends on internet speed
• Local caching can improve mounted drive performance

CHAPTER 4: SMB/CIFS NETWORK SHARES
═══════════════════════════════════════════════════════════════════════════

4.1 ADDING SMB SHARES
─────────────────────────────────────────────────────────────────────────

SMB (Server Message Block) is the standard Windows file sharing protocol.

BASIC SETUP:
1. Protocol: Select "SMB"
2. Path Format: \\server\sharename
   Examples:
   - \\192.168.1.50\Media
   - \\FILESERVER\Public
   - \\nas.local\backup

3. Authentication:
   - Domain users: DOMAIN\username
   - Local users: username
   - Leave blank for guest access

TIPS FOR PATH ENTRY:
• Use IP addresses for more reliable connections
• Server names require DNS or WINS resolution
• Avoid spaces in share names when possible
• Case doesn't matter for Windows shares


4.2 AUTHENTICATION
─────────────────────────────────────────────────────────────────────────

THREE AUTHENTICATION SCENARIOS:

1. GUEST ACCESS (No Credentials)
   - Leave username and password blank
   - Works for public shares
   - Limited permissions

2. LOCAL USER
   - Username: admin
   - Password: password123
   - Authenticates against server's local accounts

3. DOMAIN USER
   - Username: COMPANY\john.doe
   - Password: domain_password
   - Authenticates against Active Directory

SECURITY NOTE:
Credentials are stored in plain text in network_vault.json
See Security Considerations (Chapter 15.2) for details.


4.3 SERVER CONNECTION MANAGEMENT
─────────────────────────────────────────────────────────────────────────

DriveMapper Pro implements intelligent server-level connection management
to avoid Windows error 1219.

HOW IT WORKS:
1. When you add multiple shares from the same server, DriveMapper Pro
   groups them together

2. Before mapping drives, it establishes a connection to the server's
   IPC$ share (administrative share) with your credentials

3. Subsequent drive mappings use this existing server session instead
   of creating new authenticated connections

4. This prevents error 1219: "Multiple connections to a server...using
   more than one user name, are not allowed"

VISUAL INDICATORS:
In the "Saved Drive Profiles" section, drives are grouped by server:

    📁 Server: \\192.168.1.50
    Z: | Media Server | SMB | User: admin
    Y: | Documents | SMB | User: admin
    X: | Photos | SMB | User: admin
    
    📁 Server: \\192.168.1.51
    W: | Backup | SMB | User: backup_user

This grouping shows that Z:, Y:, and X: all connect to the same server
and MUST use the same credentials.


4.4 ERROR 1219 EXPLAINED
─────────────────────────────────────────────────────────────────────────

WHAT IS ERROR 1219?
Full error message:
"Multiple connections to a server or shared resource by the same user,
using more than one user name, are not allowed. Disconnect all previous
connections to the server or shared resource and try again."

WHY IT HAPPENS:
Windows only allows ONE set of credentials per server. If you try to
map multiple shares from the same server with different usernames or
passwords, Windows refuses the connection.

COMMON CAUSES:
1. Mapping shares with different usernames
2. Mixing authenticated and non-authenticated connections
3. Previous connections not properly closed

HOW DRIVEMAPPER PRO FIXES IT:
1. SERVER PREPARATION
   Click "🔧 Prepare" to establish server connections before mapping

2. AUTOMATIC GROUPING
   DriveMapper Pro detects shares from the same server and ensures
   they use the same credentials

3. CLEAR CONNECTIONS
   Click "🔓 Clear" to disconnect all server sessions and start fresh

MANUAL RESOLUTION:
If you encounter error 1219:
1. Click "⏹ Disconnect All" to clear everything
2. Ensure all drives from the same server use SAME credentials
3. Click "🔧 Prepare" to establish server connections
4. Click "▶▶ Map All" to map all drives


4.5 MULTIPLE SHARES FROM SAME SERVER
─────────────────────────────────────────────────────────────────────────

BEST PRACTICES:

1. USE CONSISTENT CREDENTIALS
   If mapping \\192.168.1.50\c, \\192.168.1.50\d, \\192.168.1.50\e
   ALL of them must use the SAME username and password

2. USE THE CLONE FEATURE
   After adding the first share:
   - Click "📋 Clone" on that drive
   - Change only the path (e.g., \c → \d)
   - Click "Validate & Add"
   - Credentials are automatically the same!

3. PREPARE BEFORE MAPPING
   For multiple drives from the same server:
   Step 1: Click "🔧 Prepare"
   Step 2: Wait for success message
   Step 3: Click "▶▶ Map All"

EXAMPLE WORKFLOW:
You have 4 shares on \\192.168.1.50:
- \\192.168.1.50\c (C drive)
- \\192.168.1.50\d (D drive)
- \\192.168.1.50\e (E drive)
- \\192.168.1.50\f (F drive)

Step 1: Add the first share (Z: → \\192.168.1.50\c)
        Username: admin
        Password: password123

Step 2: Click "📋 Clone" on Z:
        Change path to \\192.168.1.50\d
        Drive letter auto-fills as Y:
        Click "Validate & Add"

Step 3: Repeat for remaining shares

Step 4: Click "🔧 Prepare"

Step 5: Click "▶▶ Map All"

Result: All 4 drives mapped using the same credentials

5.1 CONFIGURING RCLONE REMOTES
─────────────────────────────────────────────────────────────────────────

Before you can use cloud storage in DriveMapper Pro, you must configure
rclone remotes.

WHAT IS A REMOTE?
A "remote" is rclone's term for a configured cloud storage connection.
Each remote has a name (like "gdrive" or "onedrive") and authentication
details.

CONFIGURING A REMOTE:

METHOD 1: Using DriveMapper Pro
1. Click "☁️ Rclone Config" button in the header
2. A console window opens with rclone config
3. Choose "n" for New remote
4. Enter a name (e.g., "gdrive")
5. Choose provider (e.g., "drive" for Google Drive)
6. Follow authentication prompts
7. Type "q" to quit when done

METHOD 2: Command Line
1. Open Command Prompt
2. Run: rclone config
3. Follow the same steps as above

EXAMPLE: Google Drive Setup
```
n) New remote
name> gdrive
Storage> drive
client_id> [Press Enter for default]
client_secret> [Press Enter for default]
scope> 1  (Full access)
root_folder_id> [Press Enter]
service_account_file> [Press Enter]
Edit advanced config? n
Use auto config? Y
[Browser opens for authorization]
Configure this as a team drive? n
y) Yes this is OK
q) Quit config
```

VERIFICATION:
After configuration, test your remote:
    rclone lsd remotename:

Example:
    rclone lsd gdrive:

You should see your Google Drive folders listed.

5.3 MOUNTING CLOUD DRIVES
─────────────────────────────────────────────────────────────────────────

Once you have a configured remote, you can mount it as a drive letter.

ADDING A CLOUD DRIVE:

1. Protocol: Select "Cloud (Rclone)"

2. Drive Letter: Choose available letter (e.g., C)

3. Path: Enter remote name with colon
   Format: remotename:path
   
   Examples:
   - gdrive:            (Root of Google Drive)
   - gdrive:Backup      (Backup folder in Google Drive)
   - onedrive:Documents (Documents folder in OneDrive)
   - dropbox:/Photos    (Photos folder in Dropbox)

4. Authentication: Leave blank (handled by rclone config)

5. Click "Validate & Add"

6. Click "▶ Map" to mount the drive

MOUNTING OPTIONS:
Rclone mount uses VFS (Virtual File System) with these defaults:
- Cache mode: writes
- No console window
- Background operation

PERFORMANCE:
Cloud mounts may have latency depending on:
• Internet connection speed
• Cloud provider's servers
• File sizes
• Cache settings


5.4 PERFORMANCE OPTIMIZATION
─────────────────────────────────────────────────────────────────────────

TIPS FOR FASTER CLOUD DRIVES:

1. USE CACHING
   Rclone caches file data locally for faster access
   Default: --vfs-cache-mode writes
   Advanced: Can be changed to "full" for aggressive caching

2. STABLE INTERNET CONNECTION
   • Wired connection preferred over WiFi
   • Minimum 10 Mbps for good performance
   • Low latency important for metadata operations

3. LIMIT SIMULTANEOUS OPERATIONS
   Don't copy hundreds of small files at once
   Cloud providers rate-limit requests

4. USE APPROPRIATE PROVIDERS
   For frequent access: Google Drive, OneDrive (good performance)
   For archival: Backblaze B2, Glacier (slower but cheaper)

5. REGIONAL CONSIDERATIONS
   Choose cloud provider with servers near your location

ADVANCED RCLONE FLAGS:
For power users, you can manually add flags when mounting:
```bash
rclone mount gdrive: X: --vfs-cache-mode full --vfs-cache-max-size 10G
```

This enables full caching with 10GB cache limit.

CHAPTER 6: SFTP & WEBDAV
═══════════════════════════════════════════════════════════════════════════

6.1 SFTP CONNECTIONS
─────────────────────────────────────────────────────────────────────────

SFTP (SSH File Transfer Protocol) provides secure file access to remote
servers over SSH.

ADDING AN SFTP DRIVE:

1. Protocol: Select "SFTP"

2. Drive Letter: Choose available letter

3. Path: Enter hostname or IP
   Examples:
   - myserver.com
   - 192.168.1.100
   - sftp.example.com

4. Username: SSH username

5. Password: SSH password
   NOTE: Key-based authentication requires rclone config

6. Click "Validate & Add" then "Map"

ON-THE-FLY SFTP:
DriveMapper Pro creates an on-the-fly rclone remote for SFTP without
requiring manual rclone configuration. The credentials you enter are
passed directly to rclone.

Format used internally:
:sftp,host=hostname,user=username,pass=password:

LIMITATIONS:
• Password authentication only (for quick setup)
• For key-based auth, use rclone config and "Cloud (Rclone)" protocol
• Performance depends on server and network


6.2 WEBDAV CONNECTIONS
─────────────────────────────────────────────────────────────────────────

WebDAV provides file access over HTTP/HTTPS.

COMMON WEBDAV SERVERS:
• Nextcloud
• ownCloud
• SharePoint
• Box
• Many NAS devices

ADDING A WEBDAV DRIVE:

1. Protocol: Select "WebDAV"

2. Drive Letter: Choose available letter

3. Path: Enter hostname (WITHOUT https://)
   Examples:
   - cloud.example.com
   - nextcloud.myserver.com
   - 10.0.0.50

4. Username: WebDAV username

5. Password: WebDAV password

6. Click "Validate & Add" then "Map"

HTTPS:
DriveMapper Pro automatically uses HTTPS for WebDAV connections.

ON-THE-FLY WEBDAV:
Similar to SFTP, WebDAV is configured on-the-fly:
:webdav,url=https://hostname,user=username,pass=password:


6.3 ON-THE-FLY REMOTES
─────────────────────────────────────────────────────────────────────────

WHAT ARE ON-THE-FLY REMOTES?
Instead of pre-configuring remotes in rclone, DriveMapper Pro can create
temporary remotes using special syntax.

BENEFITS:
• No rclone configuration needed
• Quick one-time access
• Credentials entered in DriveMapper Pro UI

DRAWBACKS:
• Limited to basic authentication
• No advanced options
• Not saved in rclone config

WHEN TO USE EACH:

Use On-The-Fly (SFTP/WebDAV protocols):
• Quick temporary access
• Simple password authentication
• One-time connections

Use Rclone Config (Cloud protocol):
• Permanent remotes
• OAuth authentication (Google, Microsoft, etc.)
• Advanced options needed

CHAPTER 7: NFS (NETWORK FILE SYSTEM)
═══════════════════════════════════════════════════════════════════════════

7.1 NFS PREREQUISITES
─────────────────────────────────────────────────────────────────────────

NFS is primarily used for Linux/Unix file sharing.

WINDOWS NFS CLIENT:
Windows 10/11 Pro and Enterprise include an NFS client, but it's not
enabled by default.

ENABLING NFS CLIENT:

Method 1: Settings (Windows 10/11)
1. Open Settings
2. Apps → Optional Features
3. Add a feature
4. Search for "NFS"
5. Install "Services for NFS"
6. Reboot

Method 2: Control Panel
1. Control Panel → Programs and Features
2. Turn Windows features on or off
3. Check "Services for NFS"
4. Click OK
5. Reboot

Method 3: PowerShell (Administrator)
```powershell
Enable-WindowsOptionalFeature -Online -FeatureName ServicesForNFS-ClientOnly
```

VERIFICATION:
Open Command Prompt and run:
    showmount -e nfs_server_ip

If you see exports listed, NFS client is working.


7.2 ADDING NFS SHARES
─────────────────────────────────────────────────────────────────────────

PATH FORMAT:
NFS uses a different format than SMB:
    server_ip:/export/path

Examples:
- 10.0.0.50:/mnt/storage
- 192.168.1.100:/export/share
- nfs.server.com:/data

ADDING AN NFS DRIVE:

1. Protocol: Select "NFS"

2. Drive Letter: Choose available letter

3. Path: Enter NFS export path
   Format: server:/path
   Example: 10.0.0.50:/mnt/storage

4. Authentication: Leave blank (NFS uses host-based authentication)

5. Click "Validate & Add" then "Map"

NFS MOUNT OPTIONS:
DriveMapper Pro uses basic NFS mount options:
    mount -o anon server:/path X:

For advanced options, you may need to use Windows mount command directly.


7.3 TROUBLESHOOTING NFS
─────────────────────────────────────────────────────────────────────────

COMMON NFS ISSUES:

1. "NFS client is not installed"
   Solution: Install NFS client (see 7.1)

2. "Network path not found"
   Causes:
   - NFS server not accessible
   - Export path incorrect
   - Firewall blocking port 2049
   Solution: Test with: showmount -e server_ip

3. "Access denied"
   Causes:
   - NFS export not configured for your IP
   - Insufficient permissions
   Solution: Check NFS server export configuration

4. "Operation not supported"
   Causes:
   - NFSv4 vs NFSv3 incompatibility
   - Server doesn't support requested operation
   Solution: Verify NFS version compatibility

NFS SERVER CONFIGURATION (Linux):
On the NFS server, ensure exports are configured:
```bash
# /etc/exports
/mnt/storage    10.0.0.0/24(rw,sync,no_subtree_check)
```

Then restart NFS:
```bash
sudo exportfs -ra
sudo systemctl restart nfs-server
```

8.1 WAKE-ON-LAN
─────────────────────────────────────────────────────────────────────────

Wake-on-LAN (WoL) allows you to wake up sleeping or powered-off network
devices remotely.

USE CASE:
Your NAS or server goes to sleep to save power. Before mapping drives,
you want to wake it up automatically.

SETUP REQUIREMENTS:

On the Target Device (NAS/Server):
1. Enable WoL in BIOS/UEFI
2. Enable WoL in network adapter settings
3. Note the MAC address of the network adapter

On DriveMapper Pro:
1. When adding a drive, enter the MAC address
   Format: AA:BB:CC:DD:EE:FF
   Also accepts: AA-BB-CC-DD-EE-FF

USING WOL:

1. Locate your drive in "Saved Drive Profiles"
2. Click "⚡ Wake" button
3. Magic packet is sent to the device
4. Wait 10-30 seconds for device to wake up
5. Click "▶ Map" to map the drive

TIPS:
• Wired connections work better than WiFi for WoL
• Some routers may block WoL packets
• Device must support WoL (check manual)
• Power saving modes affect WoL reliability

TECHNICAL DETAILS:
WoL sends a "magic packet" containing:
- 6 bytes of 0xFF (broadcast)
- 16 repetitions of the target MAC address
- Sent as UDP broadcast on port 9


8.2 CLONE DRIVE FEATURE

The Clone feature is a time-saver when adding multiple similar drives.

WHEN TO USE:

8.4 SERVER PREPARATION
─────────────────────────────────────────────────────────────────────────

The "Prepare" button establishes server-level connections before mapping
drives. This is crucial for avoiding error 1219.

HOW IT WORKS:

1. Click "🔧 Prepare" button

2. DriveMapper Pro analyzes your saved drives

3. Groups drives by server address

4. For each unique server:
   - Connects to \\server\IPC$ with credentials
   - Establishes authenticated session
   - Stores connection information

5. Shows success message:
   "Successfully connected to X server(s)"

WHEN TO USE:

Use "Prepare" before:
• Mapping multiple drives from same server
• After clicking "Clear Servers"
• After a network disconnect
• On application startup

DON'T NEED "Prepare" for:
• Single drive mapping
• Drives from different servers
• Cloud/SFTP/WebDAV drives (they don't use server connections)

WORKFLOW:
1. Configure all your drives
2. Click "🔧 Prepare"
3. Click "▶▶ Map All"

This ensures all server connections are established with the correct
credentials before any drive mapping attempts.


8.5 BULK OPERATIONS
─────────────────────────────────────────────────────────────────────────

BULK OPERATIONS:

▶▶ MAP ALL:
Maps all saved drive configurations in one click.

Process:
1. Automatically runs "Prepare Servers"
2. Waits 1 second for connections to establish
3. Maps each drive in sequence
4. Shows summary: "Successfully mapped: X, Failed: Y"
5. Refreshes status display

Best used:
- On application startup
- After system reboot
- After network reconnection

⏹ DISCONNECT ALL:
Disconnects all network drives and stops all mounts.

Process:
1. Runs: net use * /delete /yes (disconnects all SMB drives)
2. Runs: taskkill /f /im rclone.exe (stops all rclone mounts)
3. Clears server connection cache
4. Shows confirmation: "All network drives have been disconnected"

Best used:
- Before system shutdown
- When switching networks
- To resolve connection issues
- Before reconfiguring drives

🔓 CLEAR SERVERS:
Clears server-level connections without disconnecting drives.

Process:
1. Disconnects from each server's IPC$ share
2. Clears server connection cache
3. Leaves actual drive mappings intact

Best used:
- Before changing credentials
- When encountering error 1219
- To reset authentication state

DIFFERENCE BETWEEN "DISCONNECT ALL" AND "CLEAR SERVERS":

Disconnect All:
- Unmaps ALL drives (they disappear from File Explorer)
- Stops all rclone processes
- Complete clean slate

Clear Servers:
- Keeps drives mapped
- Only clears authentication sessions
- Use when drives are working but you need to change credentials

CHAPTER 9: SYNC MANAGER OVERVIEW

9.1 WHAT IS SYNC MANAGER?
─────────────────────────────────────────────────────────────────────────

Sync Manager is a profile-based synchronization tool that uses rclone
to keep directories synchronized.

KEY FEATURES:
• Bidirectional sync (keeps both sides identical)
• One-way sync (copies from source to destination)
• Works with any combination of local, cloud, SMB, FTP
• Conflict resolution strategies
• Named profiles for different sync tasks
• Progress monitoring and logging

RCLONE INTEGRATION:
Sync Manager uses two rclone commands:
- rclone bisync: Bidirectional synchronization
- rclone sync: One-way synchronization


9.2 USE CASES
─────────────────────────────────────────────────────────────────────────

BACKUP & DISASTER RECOVERY:
• Backup documents to cloud storage
• Mirror important files to external drive
• Offsite backup to remote server

MULTI-LOCATION WORKFLOWS:
• Sync laptop and desktop computers
• Keep home and office files synchronized
• Collaborate across multiple devices

CLOUD TO CLOUD:
• Copy Google Drive to OneDrive
• Backup one cloud provider to another
• Migrate between cloud services

DEVELOPMENT:
• Sync code between local and remote servers
• Keep multiple dev environments synchronized
• Backup project files to cloud

MEDIA MANAGEMENT:
• Sync photo library to NAS
• Backup video files to cloud storage
• Mirror media collection across devices


9.3 SYNC VS BACKUP
─────────────────────────────────────────────────────────────────────────

UNDERSTANDING THE DIFFERENCE:

SYNC (Bidirectional):
• Changes propagate in both directions
• Keeps two locations identical
• Deleting on one side deletes on other
• Use for: Active collaboration, multi-device workflows

SYNC (One-Way):
• Changes go from source to destination only
• Destination mirrors source
• Can delete files on destination that don't exist in source
• Use for: Backups, archival, mirroring

BACKUP (Not just sync):
True backup includes:
• Version history (rclone doesn't do this natively)
• Point-in-time recovery
• Deletion protection

Sync Manager provides sync, not comprehensive backup. For critical data:
• Use multiple backup strategies
• Keep offline backups
• Test recovery procedures
• Use versioning cloud storage

WHEN TO USE SYNC MANAGER:
✓ Keeping folders synchronized
✓ One-way backups to cloud/server
✓ Mirroring directories
✓ Development workflows

WHEN NOT TO USE SYNC MANAGER:
✗ Recovering accidentally deleted files (no version history)
✗ Point-in-time restore
✗ Ransomware protection (sync will propagate encryption)

CHAPTER 10: CREATING SYNC PROFILES
═══════════════════════════════════════════════════════════════════════════

10.1 PROFILE CONFIGURATION
─────────────────────────────────────────────────────────────────────────

A sync profile defines a synchronization task with all its settings.

PROFILE FIELDS:

1. Profile Name
   - Descriptive name for this sync task
   - Examples: "Documents Backup", "Photo Sync", "Work Files"
   - Used in UI and log files

2. Source Location
   - Where to sync FROM
   - Can be local path, UNC path, or rclone remote

3. Destination Location
   - Where to sync TO
   - Same format options as source

4. Sync Options (Checkboxes)
   - Bidirectional (bisync)
   - Delete files on destination
   - Check access
   - Force resync

5. Conflict Resolution
   - Strategy for handling conflicts
   - See section 10.5


10.2 SOURCE AND DESTINATION
─────────────────────────────────────────────────────────────────────────

LOCATION FORMATS:

Local Directory:
    C:\Users\Me\Documents
    D:\Photos
    E:\Projects

UNC Path (Network Share):
    \\192.168.1.50\Media
    \\server\backup
    \\nas\photos

Rclone Remote:
    gdrive:Backup
    onedrive:Documents
    dropbox:/Photos

Mixed Examples:
    Source: C:\Documents
    Dest:   gdrive:Backup/Documents
    
    Source: \\192.168.1.50\Media
    Dest:   onedrive:MediaBackup
    
    Source: gdrive:Work
    Dest:   dropbox:/WorkBackup

BROWSING:
Click "📁 Browse" button to select local directories.
For network shares and cloud remotes, type them manually.

PATH TIPS:
• Use forward slashes OR backslashes (Windows accepts both)
• Trailing slashes matter for some operations
• Spaces in paths are okay
• Quote paths with spaces if using manual rclone commands


10.3 BIDIRECTIONAL VS ONE-WAY
─────────────────────────────────────────────────────────────────────────

BIDIRECTIONAL SYNC (BISYNC):

What it does:
• Tracks changes on both sides
• Synchronizes changes in both directions
• Keeps both locations identical

How it works:
1. First run creates baseline listings
2. Subsequent runs detect changes on each side
3. Applies changes to opposite side
4. Handles conflicts based on resolution strategy

Use when:
• You work on multiple computers
• Collaborating with shared folders
• Want automatic two-way sync
• Both sides are "active"

Example:
Laptop Documents ⟷ Desktop Documents
Changes on laptop sync to desktop, vice versa

Requirements:
• Source and destination must be accessible
• Both sides must be in consistent state
• First run needs --resync flag


ONE-WAY SYNC:

What it does:
• Copies from source to destination
• Destination becomes mirror of source
• Source remains unchanged

How it works:
1. Lists files in source
2. Compares with destination
3. Copies new/changed files to destination
4. Optionally deletes extra files on destination

Use when:
• Creating backups
• Source is primary, destination is copy
• Only care about preserving source
• Don't want changes on destination

Example:
C:\Documents → gdrive:Backup
Anything in C:\Documents is backed up to Google Drive

Caution:
With "delete on destination" enabled, files only in destination
will be deleted!


10.4 SYNC OPTIONS
─────────────────────────────────────────────────────────────────────────

OPTION: BIDIRECTIONAL (BISYNC)
☑ Enabled: Uses rclone bisync for two-way sync
☐ Disabled: Uses rclone sync for one-way sync

Impact:
Changes which rclone command is used and sync behavior.


OPTION: DELETE FILES ON DESTINATION
(Only for one-way sync)

☑ Enabled: Files on destination not in source are deleted
☐ Disabled: Extra files on destination are left alone

Example:
Source has: file1.txt, file2.txt
Dest has:   file1.txt, file2.txt, file3.txt

With delete enabled:
After sync, dest has: file1.txt, file2.txt
(file3.txt was deleted)

With delete disabled:
After sync, dest has: file1.txt, file2.txt, file3.txt
(file3.txt kept)

Caution:
Use carefully! Can cause data loss if misconfigured.


OPTION: CHECK ACCESS (RECOMMENDED FOR BISYNC)
☑ Enabled: Adds --check-access flag
☐ Disabled: No access checking

What it does:
Creates RCLONE_TEST file in both locations to verify write access.
If files are missing, bisync aborts to prevent data loss.

Recommendation:
Always enable for bidirectional sync.
Prevents accidental one-way sync if destination is inaccessible.


OPTION: FORCE RESYNC (INITIAL SYNC)
☑ Enabled: Runs with --resync flag
☐ Disabled: Normal sync

When to enable:
• First sync of a profile
• After changes outside DriveMapper Pro
• To rebuild sync database
• After conflicts or errors

What it does:
Recreates baseline listings without sync direction history.
All files copied to bring sides into sync.

Auto-clear:
DriveMapper Pro automatically disables this after first successful run.


10.5 CONFLICT RESOLUTION
─────────────────────────────────────────────────────────────────────────

When the same file is modified on both sides, a conflict occurs.

RESOLUTION STRATEGIES:

NONE (Default):
• Rclone creates duplicate files with conflict suffix
• Both versions preserved
• You manually resolve later
• Safest option

Example conflict:
    document.txt
    document.conflict1.txt

NEWER:
• Keeps the version with most recent modification time
• Older version is overwritten
• Based on file timestamps

Use when:
• Time-based resolution makes sense
• Clock sync is accurate

OLDER:
• Keeps the version with earliest modification time
• Newer version is overwritten
• Unusual but available

Use when:
• Want to preserve original version
• Prevent overwrites of established content

LARGER:
• Keeps the version with larger file size
• Smaller version is overwritten

Use when:
• Larger = more complete
• File size indicates which is better

SMALLER:
• Keeps the version with smaller file size
• Larger version is overwritten

Use when:
• Want compressed versions
• Larger files are temporary/cache

PATH1:
• Always prefer source (path1) version
• Destination version is overwritten

Use when:
• Source is authoritative
• Want one-way priority

PATH2:
• Always prefer destination (path2) version
• Source version is overwritten

Use when:
• Destination is authoritative
• Backup location is primary

RECOMMENDATION:
Start with "newer" for most use cases.
Change to "none" if you want to manually review conflicts.

2. Press Ctrl+C in console

13.1 ERROR 1219 RESOLUTION
─────────────────────────────────────────────────────────────────────────

FULL ERROR:
"Multiple connections to a server or shared resource by the same user,
using more than one user name, are not allowed."

ROOT CAUSE:
Windows only allows one set of credentials per server.

SYMPTOMS:
• Can map first drive from server successfully
• Second drive from same server fails with error 1219
• Error occurs even with same username

SOLUTION 1: USE PREPARE BUTTON
1. Click "🔓 Clear" to clear existing connections
2. Ensure all drives from same server have SAME credentials
3. Click "🔧 Prepare" to establish server connections
4. Click "▶▶ Map All"

SOLUTION 2: DISCONNECT AND REMAP
1. Click "⏹ Disconnect All"
2. Verify all \\server shares use identical credentials in configs
3. Click "▶▶ Map All"

SOLUTION 3: MANUAL FIX
1. Open Command Prompt as Administrator
2. Run: net use * /delete /yes
3. Run: net use \\server\IPC$ /user:username password
4. Now map drives in DriveMapper Pro

PREVENTION:
• Use "Clone" feature to ensure same credentials
• Check credentials before adding multiple shares
• Use "Prepare" before "Map All"

VERIFICATION:
Check that all shares from same server have identical:
- Username field
- Password field
Empty vs filled counts as different!


13.2 DRIVE NOT SHOWING IN STATUS
─────────────────────────────────────────────────────────────────────────

SYMPTOM:
Drive is mapped (visible in File Explorer) but doesn't appear in
"Live Drive Status" panel.

DIAGNOSIS:

Step 1: Click "🔄 Refresh"
Wait 2-3 seconds and see if drive appears.

Step 2: Click "🔍 Test"
Compare three detection methods:
- net use command
- PowerShell Get-PSDrive
- Python win32api

If drive shows in "net use" but not win32api, the dual-method detection
should still catch it.

Step 3: Check Logs
Open drive_events.log and look for:
- "DEBUG: net use detected X:"
- "DEBUG: win32api detected X:"

SOLUTIONS:

If drive is in "net use" but not status:
• Bug in status refresh - report this
• Drive is mapped correctly, just display issue
• Use File Explorer to access drive

If drive is NOT in "net use":
• Drive didn't actually map
• Check for error messages in log
• Try mapping again

If neither detection method sees it:
• Drive may be local, not network
• Drive type may not be 4 (network)
• Use "net use" command manually to verify


13.3 AUTHENTICATION FAILURES
─────────────────────────────────────────────────────────────────────────

ERROR CODES:

Error 1326: "Logon failure: unknown user name or bad password"
Cause: Incorrect username or password
Solution:
- Double-check credentials
- Verify caps lock is off
- Try logging in via Windows Explorer first
- Check if account is locked

Error 5: "Access is denied"
Cause: Insufficient permissions
Solution:
- Verify user has access to the share
- Check share permissions on server
- Check NTFS permissions on server
- Try with administrator account

Error 53: "The network path was not found"
Cause: Server or share doesn't exist
Solution:
- Verify server is online: ping server_ip
- Check share name spelling
- Verify share exists on server
- Try \\server without share name

Error 64: "The specified network name is no longer available"
Cause: Network connection lost
Solution:
- Check network cable/WiFi
- Verify server is still online
- Check for network interruptions
- May need to disconnect and reconnect

DOMAIN AUTHENTICATION:
For domain users:
- Username format: DOMAIN\username
- Don't use email address
- Must be on domain network or VPN

TROUBLESHOOTING STEPS:
1. Test credentials in Windows Explorer
   - Press Win+R
   - Type: \\server\share
   - Enter credentials when prompted
   
2. If Explorer works but DriveMapper fails:
   - Copy exact path from Explorer
   - Ensure credentials match exactly
   
3. Check server-side logs
   - View security logs on server
   - Look for failed login attempts
   - Verify account isn't locked


13.4 SYNC CONFLICTS
─────────────────────────────────────────────────────────────────────────

WHAT IS A CONFLICT?
When the same file is modified on both sides between syncs.

SYMPTOMS:
• Files with .conflict suffix appear
• Sync log shows "conflict" messages
• Multiple versions of same file exist

FINDING CONFLICTS:
1. Open sync log file
2. Search for "conflict"
3. Look for lines like:
   "NOTICE: file.txt: bisync: conflict: file modified on both sides"

RESOLUTION BY STRATEGY:

If conflict_resolve = "none":
• Both versions are kept
• Conflicted file renamed with suffix
Example:
    document.txt (original from one side)
    document.conflict1.txt (version from other side)

Manual resolution:
1. Open both files
2. Determine which to keep
3. Delete unwanted version
4. Rename if needed
5. Run sync again

If conflict_resolve = "newer/older/larger/smaller/path1/path2":
• Rclone automatically resolves
• One version overwrites the other
• Lost version cannot be recovered

PREVENTION:
• Don't edit same file on multiple devices simultaneously
• Sync frequently to minimize divergence
• Use unique filenames when possible
• Add timestamps to filenames
• Consider using version control (Git) for critical files


13.5 PERFORMANCE ISSUES
─────────────────────────────────────────────────────────────────────────

SLOW DRIVE ACCESS:

For Cloud Drives:
Cause: Internet latency, poor caching
Solutions:
- Use wired connection, not WiFi
- Increase rclone cache size
- Pre-download frequently used files
- Consider local copy with periodic sync

For SMB Shares:
Cause: Network congestion, slow server
Solutions:
- Check network utilization
- Verify server performance
- Use gigabit ethernet
- Reduce simultaneous connections

For SFTP/WebDAV:
Cause: Protocol overhead, encryption
Solutions:
- Use SMB if possible (faster)
- Reduce transfer sizes
- Enable compression (rclone flags)


SLOW SYNC:

Small Files:
Cause: Overhead of many operations
Solutions:
- Archive small files
- Use --transfers flag to increase parallel transfers
- Consider compression

Large Files:
Cause: Transfer time
Solutions:
- Use --max-size to exclude huge files
- Sync during off-hours
- Increase bandwidth
- Enable multipart uploads (for cloud)

First Sync:
Cause: Everything must be transferred
Solutions:
- Be patient!
- Run overnight for large datasets
- Use --dry-run first to estimate time
- Consider physical media for initial transfer (if very large)


GENERAL PERFORMANCE TIPS:
• Close unnecessary applications
• Disable antivirus scanning of network drives (temporarily)
• Use dedicated network connection for sync
• Schedule syncs during off-peak hours
• Monitor network bandwidth usage

17.1 HOW SERVER CONNECTIONS WORK
─────────────────────────────────────────────────────────────────────────

WINDOWS SMB ARCHITECTURE:

When you map a drive, Windows:
1. Establishes TCP connection to server (port 445)
2. Negotiates SMB protocol version
3. Authenticates user (if credentials provided)
4. Opens session to specific share
5. Assigns drive letter
6. Maintains connection

SERVER-LEVEL vs SHARE-LEVEL:

Server-Level Connection:
• Connection to \\server\IPC$
• Authenticated session with username/password
• ONE per server
• Shared by all shares on that server

Share-Level Connection:
• Connection to specific share (\\server\sharename)
• Uses existing server session
• Multiple per server
• Each gets own drive letter

DRIVEMAPPER PRO APPROACH:

Traditional Windows Mapping (without DriveMapper Pro):
```
Map Z: -> Authenticate to \\server\share1
Map Y: -> Try to authenticate to \\server\share2
ERROR 1219 if different credentials!
```

DriveMapper Pro Method:
```
Authenticate to \\server\IPC$ (server-level)
Map Z: -> Use existing session for \\server\share1
Map Y: -> Use existing session for \\server\share2
SUCCESS!
```

IPC$ SHARE:
• Administrative share
• Used for inter-process communication
• Allows server-level authentication
• Does not appear as mapped drive
• Only used for establishing session

TECHNICAL DETAILS:

WNetAddConnection2 API:
DriveMapper Pro uses Windows API:
```
WNetAddConnection2(
    NETRESOURCE,     // Specifies path and drive letter
    password,        // Password (or NULL)
    username,        // Username (or NULL)
    flags           // Connection options
)
```

First call (to IPC$): Establishes session
Subsequent calls: Use NULL for credentials (uses existing session)


17.2 WINDOWS NETWORK STACK
─────────────────────────────────────────────────────────────────────────

NETWORK LAYERS:

Application Layer:
• DriveMapper Pro
• Windows Explorer
• File operations

SMB Protocol Layer:
• SMB3, SMB2, SMB1
• File sharing protocol
• Authentication and encryption

Transport Layer:
• TCP/IP
• Port 445 (SMB)
• Port 139 (NetBIOS - legacy)

Network Layer:
• Ethernet/WiFi
• Physical network connection

PROTOCOLS USED:

SMB/CIFS:
• Modern: SMB3 (fastest, most secure)
• Compatible: SMB2
• Legacy: SMB1 (disabled by default, security risk)

NetBIOS:
• Legacy name resolution
• Port 139
• Not needed for modern networks

DNS:
• Name resolution
• Converts servername to IP address
• Required for using server names instead of IPs

WINS:
• Windows Internet Name Service
• Legacy NetBIOS name resolution
• Not commonly used anymore

AUTHENTICATION METHODS:

NTLM:
• NT LAN Manager
• Challenge-response authentication
• Works without domain

Kerberos:
• Domain-based authentication
• More secure than NTLM
• Requires Active Directory

Guest:
• No authentication
• Limited permissions
• Insecure

NETWORK DISCOVERY:

How Windows finds servers:
1. DNS lookup for server name
2. LLMNR (Link-Local Multicast Name Resolution)
3. NetBIOS broadcast (if enabled)
4. Direct IP address connection

Why IP addresses are more reliable:
• Skip name resolution steps
• Work even if DNS/LLMNR/NetBIOS fail
• Faster connection establishment


17.3 SECURITY & PERMISSIONS
─────────────────────────────────────────────────────────────────────────

SHARE PERMISSIONS:

Set on SMB server, control WHO can access share:
• Full Control
• Change
• Read

Applied at share level, checked first.

NTFS PERMISSIONS:

Set on files/folders, control WHAT users can do:
• Full Control
• Modify
• Read & Execute
• Read
• Write

Applied at file level, checked second.

EFFECTIVE PERMISSIONS:
Combination of share and NTFS permissions.
Most restrictive wins.

Example:
Share: Full Control
NTFS: Read
Result: Read only

PERMISSION TROUBLESHOOTING:

"Access Denied" errors:
1. Check share permissions on server
2. Check NTFS permissions on specific files/folders
3. Verify user account has access
4. Check group memberships
5. Try with administrator account

SECURITY BEST PRACTICES:

Principle of Least Privilege:
• Grant minimum necessary permissions
• Don't use administrator accounts for regular access
• Create separate accounts for different purposes

Network Segmentation:
• Use VLANs to separate sensitive data
• Firewall rules between segments
• Limit SMB to internal network only

Encryption:
• Enable SMB3 encryption
• Use VPN for remote access
• HTTPS for WebDAV

Audit Logging:
• Enable audit logging on SMB server
• Monitor access logs
• Alert on suspicious activity

CREDENTIAL MANAGEMENT:

Windows Credential Manager:
• Stores saved credentials
• Used for "remember my credentials"
• Can interfere with DriveMapper Pro

To view stored credentials:
1. Control Panel
2. Credential Manager
3. Windows Credentials
4. Look for server entries

To remove:
1. Find credential for server
2. Click Remove
3. Try mapping again with new credentials

DOMAIN vs WORKGROUP:

Domain Environment:
• Centralized authentication (Active Directory)
• Group Policy control
• Kerberos authentication
• More secure, easier management

Workgroup:
• Local authentication on each server
• NTLM authentication
• Each server has own user accounts
• Common for home/small business

19.4 ERROR CODES
─────────────────────────────────────────────────────────────────────────

WINDOWS ERROR CODES:

85: "The local device name is already in use"
• Drive letter already mapped
• Solution: Choose different letter or disconnect existing

53: "The network path was not found"
• Server or share doesn't exist
• Server is offline
• Solution: Verify path, check server status

1219: "Multiple connections...using more than one user name"
• Windows credential conflict
• Solution: Use Prepare button, ensure same credentials

1326: "Logon failure: unknown user name or bad password"
• Incorrect credentials
• Account locked
• Solution: Verify username/password

5: "Access is denied"
• Insufficient permissions
• Solution: Check share and NTFS permissions

64: "The specified network name is no longer available"
• Network connection lost
• Server went offline
• Solution: Check network, verify server

67: "The network name cannot be found"
• Name resolution failure
• Solution: Use IP address instead of hostname

1203: "The user has not been granted the requested logon type"
• Policy restriction
• Solution: Check server security policy

1231: "The network location cannot be reached"
• Network routing issue
• Firewall blocking
• Solution: Check network connectivity, firewall

RCLONE ERROR CODES:

Exit Code 0: Success
Exit Code 1: Syntax or usage error
Exit Code 2: Error not otherwise categorized
Exit Code 3: Directory not found
Exit Code 4: File not found
Exit Code 5: Temporary error (retry)
Exit Code 6: Less serious errors
Exit Code 7: Fatal error
Exit Code 8: Transfer exceeded --max-transfer

20.1 GENERAL QUESTIONS
─────────────────────────────────────────────────────────────────────────

Q: Do I need administrator privileges?
A: Not for most operations. Administrator needed for:
   - Installing NFS client
   - Mapping drives on some restricted systems
   - Running as Windows Service

Q: Does DriveMapper Pro work on Windows Home?
A: Yes! All features work on Windows 10/11 Home, except:
   - NFS (requires Pro/Enterprise)
   - Group Policy features (domain environments)

Q: Can I use DriveMapper Pro on multiple computers?
A: Yes. Copy the config files (network_vault.json, sync_profiles.json)
   to each computer. Adjust drive letters if needed.

Q: Will mapped drives persist after reboot?
A: Network drives mapped with DriveMapper Pro are temporary by default.
   Use "Map All" on startup (create shortcut in Startup folder) or
   modify code to add CONNECT_UPDATE_PROFILE flag.

Q: How do I uninstall DriveMapper Pro?
A: 1. Disconnect all drives
   2. Delete the application folder
   3. Remove any scheduled tasks
   That's it! No registry changes or system files.

Q: Is my data safe?
A: DriveMapper Pro doesn't modify your files. It only creates mappings
   and runs rclone commands. However:
   - Sync operations CAN delete files (if configured)
   - Always test with --dry-run first
   - Keep backups of important data


20.2 DRIVE MAPPING QUESTIONS
─────────────────────────────────────────────────────────────────────────

Q: Why can't I map more than one drive from the same server?
A: Error 1219 - Windows limitation. Solution:
   - Use "Prepare" button before mapping
   - Ensure same credentials for all shares on same server

Q: My drive shows in Explorer but not in DriveMapper Pro status.
A: Click "Refresh" or "Test" button. If neither detection method shows it,
   it may not be a true network drive (type 4).

Q: Can I map the same share to multiple drive letters?
A: Yes, but not recommended. Creates duplicate connections.

Q: Drive letter changes after reboot.
A: Drive letters are first-come-first-served. To ensure consistency:
   - Use letters Z,Y,X working backwards (less likely to conflict)
   - Map drives in same order each time
   - Avoid using common letters (D,E,F often used by USB drives)

Q: How do I map a drive without credentials?
A: Leave username and password fields blank. This attempts guest access.

Q: Can I access the same drive from multiple computers?
A: Yes! Each computer can map the same network share independently.

Q: Cloud drive is slow.
A: Normal for cloud storage. Factors:
   - Internet speed
   - Cloud provider performance
   - File sizes (many small files = slower)
   - Rclone cache settings
   
   Improvements:
   - Use --vfs-cache-mode full
   - Increase cache size
   - Pre-download frequently used files


20.3 SYNC MANAGER QUESTIONS
─────────────────────────────────────────────────────────────────────────

Q: What's the difference between bisync and sync?
A: bisync = two-way (changes go both directions)
   sync = one-way (source → destination only)

Q: Can I recover deleted files?
A: No, Sync Manager doesn't keep version history.
   Consider:
   - Cloud storage with versioning enabled
   - Separate backup strategy
   - Testing with --dry-run first

Q: How do I handle conflicts?
A: Configure conflict_resolve strategy:
   - "none": Both versions kept
   - "newer": Newest wins
   - Other strategies available

Q: Can I sync while working on files?
A: Not recommended. Results undefined. Best practice:
   - Close files before syncing
   - Don't work on both sides simultaneously
   - Sync at start/end of work session

Q: How often should I sync?
A: Depends on use case:
   - Critical data: Hourly or more
   - Regular backups: Daily
   - Archival: Weekly/monthly
   
   More frequent = less divergence = fewer conflicts

Q: Can I schedule syncs?
A: Yes! Use Windows Task Scheduler with rclone commands.
   See Chapter 15.4 for instructions.

Q: Sync is taking forever.
A: First sync transfers everything (can be slow).
   Subsequent syncs only transfer changes.
   
   For large datasets:
   - Run overnight
   - Consider initial transfer via physical media
   - Use --max-transfer to limit per-run

Q: Can I sync to multiple destinations?
A: Yes! Create separate sync profiles for each destination.
   Example:
   - Profile 1: Local → Google Drive
   - Profile 2: Local → OneDrive
   - Profile 3: Local → NAS


20.4 TECHNICAL QUESTIONS
─────────────────────────────────────────────────────────────────────────

Q: What happens if I close DriveMapper Pro?
A: Mapped drives remain mapped! DriveMapper Pro is just a management tool.
   To disconnect: Use "Disconnect All" before closing.

Q: Do I need to keep DriveMapper Pro running?
A: No. Once drives are mapped, DriveMapper Pro can be closed.
   However, running it provides:
   - Status monitoring
   - Easy disconnect
   - Quick access to sync functions

Q: How secure is storing passwords in the config file?
A: Passwords are stored in PLAIN TEXT. Security measures:
   - Set file permissions (only you can read)
   - Use BitLocker for disk encryption
   - Don't store config on network/cloud
   - Use Windows Credential Manager when possible

Q: Can I run multiple instances?
A: Not recommended. Could cause conflicts with config files.

Q: Does DriveMapper Pro use much resources?
A: Very light:
   - ~50 MB RAM
   - Minimal CPU
   - No impact when idle
   
   Rclone mounts use more resources depending on activity.

Q: Can I use DriveMapper Pro commercially?
A: Check the license. Generally:
   - Personal use: Free
   - Commercial use: May require license
   - Rclone: Open source (MIT license)

Q: How do I report bugs?
A: Check for updated versions first.
   Provide:
   - DriveMapper Pro version
   - Windows version
   - drive_events.log file
   - Steps to reproduce

Q: Can I contribute to development?
A: DriveMapper Pro is a Python application.
   You can:
   - Modify source code
   - Add features
   - Share improvements
   
   Python skills required.

CHAPTER 21: GLOSSARY
═══════════════════════════════════════════════════════════════════════════

BISYNC:
Bidirectional synchronization. Keeps two locations identical by syncing
changes in both directions.

CIFS:
Common Internet File System. Another name for SMB (Server Message Block).
Used interchangeably with SMB.

CONFLICT:
When the same file is modified on both sides of a bidirectional sync
between sync runs.

DRIVE LETTER:
Single letter (A-Z) assigned to a storage location in Windows.
Examples: C:, Z:, Y:

DRIVE MAPPING:
Process of assigning a drive letter to a network location, making it
appear as a local drive.

ERROR 1219:
Windows error preventing multiple connections to same server with
different credentials.

IPC$:
Inter-Process Communication share. Administrative share used for
server-level authentication. Doesn't appear as a mapped drive.

MOUNT:
Process of making a remote filesystem available at a local path.
In DriveMapper Pro context, used for cloud storage, SFTP, WebDAV.

NAS:
Network Attached Storage. Device providing file-level data storage
over a network.

NETRESOURCE:
Windows structure defining a network resource (used in drive mapping API).

NFS:
Network File System. Unix/Linux file sharing protocol.

ONE-WAY SYNC:
Synchronization where changes only go from source to destination.
Destination becomes mirror of source.

RCLONE:
Command-line program for syncing files with cloud storage and other
remote locations.

REMOTE:
In rclone context, a configured connection to cloud storage or remote
location.

RESYNC:
Rclone bisync operation that rebuilds baseline without sync history.
Required for first sync or after issues.

SMB:
Server Message Block. Windows file sharing protocol. Used for
network drives.

SFTP:
SSH File Transfer Protocol. Secure file transfer protocol using SSH.

SYNC PROFILE:
Named configuration defining a synchronization task with all its
settings.

UNC PATH:
Universal Naming Convention path. Format: \\server\share
Used for accessing network resources.

VFS:
Virtual File System. Rclone feature that makes cloud storage appear
as local filesystem.

WEBDAV:
Web Distributed Authoring and Versioning. HTTP-based file access
protocol.

WOL:
Wake-on-LAN. Protocol for waking up sleeping computers via network.
